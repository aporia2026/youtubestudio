# Zenn v1 — Mode B preview fallback + Mode A character-continuation cache

**Date:** 2026-06-14
**Status:** Approved
**Bug reporter:** Operator (production-doc editor session, screenshot attached to chat)

## Problem

Two issues surfaced while using the Zenn style in the production-doc editor:

1. **Mode B preview shows only color bands, never the row image.** When a row's `zenn_mode === 'scene'` the renderer paints only the CSS world bands plus a character-bank PNG. Real videos usually arrive at Mode B before the bank is populated (the bank is generated by `generating_zenn_v1_images` AFTER `generating_production_doc_images`), so the operator sees blank-band scenes in the editor preview while the bank is still pending. The row's already-generated `imageUrl` is right there, but the renderer ignores it.

2. **Characters drift between shots.** Two consecutive shots of "Sergey Korolev" generated by the per-row image pipeline rendered the same character with hair in one shot and bald in the next. zenn_v1 has no Mode A character-continuation cache — each row's `ai_image_prompt` is regenerated independently, with the model only loosely anchored by the four style refs. doodle_explainer_2 solved this in `_plans/2026-05-28-doodle-2-character-cache.md` via Atlas Edit on a cached base; zenn_v1 needs the same machinery.

## Goals

- Mode B preview never goes blank when a row has an `imageUrl`. The row image is used as a fallback backdrop when the character bank entry is missing.
- Recurring named characters in Mode A keep face / hair / clothing across shots when they share `zenn_character_id`.

## Non-goals

- Touching the LLM prompt rules (rule for emitting `zenn_character_id` stays as-is).
- Generating pose siblings for the bank (still pending PR 5).
- Adding settings UI for cache behavior — the cache is a quality fix, not a knob.

## Approach

### Bug 1 — Mode B fallback to `shot.imageUrl`

In `src/remotion/scenes/ZennScene.tsx` the Mode B branch currently always paints `<WorldBackground/>` regardless of whether a character bank entry exists.

New logic:

- If `isSceneMode` AND `characterUrl` resolves → bands + character (current behavior).
- If `isSceneMode` AND `characterUrl` is undefined AND `shot.imageUrl` exists → render the row image as the base (Mode A look) so the preview is never empty while the bank is pending.
- If `isSceneMode` AND neither resolves → bands only (defensive fallback, same as today).

Mode A (`zennMode === 'stick'` or undefined) is unchanged.

### Bug 2 — `zenn_v1_character_cache` + per-row Atlas Edit

Mirror the doodle_explainer_2 character-cache pattern exactly.

**Schema additions:**

- `ProductionDoc.zenn_v1_character_cache?: Record<string, { base_url: string; first_seen_row_index: number }>` in `src/remotion/utils.ts`.
- Same field on the inline `ProductionDoc` mirror in `src/app/(app)/production-doc/page.tsx`.
- Same field on `PipelineImageDoc` in `src/lib/auto-pipeline/production-doc-image-gen.ts`.

**Lookup key:** zenn_v1 rows carry `zenn_character_id` (not the generic `character_id` doodle_explainer_2 uses). The cache logic in the stage handler reads `row.zenn_character_id` when `doc.style_preset === 'zenn_v1'` and `row.character_id` otherwise — single branch in one place.

**Stage handler change in `generate-production-doc-images.ts`:**

Add a parallel branch next to the doodle_explainer_2 character-cache branch (~line 977). The branch:

1. Detects `isZennV1 && row.zenn_character_id?.trim()`.
2. If the cache has an entry: call `generateCharacterContinuationImage` with the cached `base_url` and the row's `ai_image_prompt` + `zenn_v1_character_descriptions`. On success, that's the row's image. On failure, fall through to fresh generation.
3. Cache miss + fresh generation succeeds → write `{ base_url: result.imageUrl, first_seen_row_index }` so subsequent rows can reuse.

**Collage eligibility:** rows with a zenn_v1 cache hit must NOT enter collage (it's a single-row edit, not a quad-cell t2i). `isCollageEligibleRow` already gates on the doodle_explainer_2 character cache; extend the same gate for zenn_v1.

**Cost:** Atlas Edit at ~$0.011 vs $0.04 fresh i2i — same delta as doodle_explainer_2.

### Observability

New log namespaces (mirroring doodle-2):

- `[zenn-v1 character-cache] hit-and-edit` — every successful cache hit.
- `[zenn-v1 character-cache] miss-and-store` — every fresh generation that populated the cache.
- `[zenn-v1 character-cache] hit but edit failed, falling back to i2i` — Atlas Edit failure.

Per-tick summary log gains `zenn_char_cache_hits`, `zenn_char_cache_misses`, `zenn_char_cache_edit_failures` counters.

## Settings audit

No new user-facing settings. The cache is an internal correctness fix, not a knob the operator should toggle.

## Security

No new attack surface. Atlas Edit is already used elsewhere in the same module with the same `workspace_id` audit attribution. No PII, no secrets.

## Testing

Unit tests:

- `tests/zenn-v1-scene.test.ts` (extend existing): a Mode B shot with `imageUrl` but no bank entry should render the image, not bare bands. A Mode B shot with neither image nor bank stays at bare bands.
- `tests/zenn-v1-character-cache.test.ts` (new): cache hit → Atlas Edit called with cached `base_url`. Cache miss → fresh generation, cache populated. Cache hit + Atlas Edit failure → falls back to fresh generation. Wrong style preset → cache branch is a no-op.

End-to-end QA (manual): generate a zenn_v1 doc with two consecutive rows sharing the same `zenn_character_id`, verify the character looks visually identical across rows.
